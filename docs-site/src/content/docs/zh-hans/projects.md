项目就是你的船员们工作的对象：一个仓库，或几个相互配套的仓库，例如一个应用和它的后台服务。
仓库是一个属于你自己、用 git 管理的文件夹。
每个任务都属于一个项目，每个任务编号都以所属项目的任务编号前缀开头，例如 `WEB-12`。
你的项目列在 **设置 → 项目** 中，点击某个项目的那一行，就会打开它的页面。

## 添加项目 {#add-a-project}

你可以用两种方式添加项目。

- **询问你的大副。**
  说出要处理哪个项目，例如说“克隆这个项目”，后面跟上它的链接。
  你的大副会给你一张卡片，写明这个项目及其设置。
  在你点击那张卡片上的 **添加项目** 之前，什么都不会添加。
- **自己添加。**
  打开 **设置 → 项目**，使用列表底部的 **添加项目** 一行。

**添加项目** 一行有三个按钮：

1. **这台电脑上的文件夹** 添加一个你已有的文件夹。
   如果这个文件夹还没有使用 git，Infinitary 会在那里初始化 git，并创建一个空的首次提交。
2. **GitHub 仓库**、**GitLab 仓库** 或 **Bitbucket 仓库** 从项目托管处克隆一个项目。
   从 **你的 GitHub 仓库** 中选择它，用 **查找仓库** 搜索，或粘贴它的链接。
   仓库很多时，可能有一些没有被检查到，列表会说明这一点；粘贴链接即可添加缺少的仓库。
3. **新项目** 用你输入的名称创建一个空项目。

克隆的项目或新项目会放进你的项目文件夹。
**新项目存放在** 一行显示这个文件夹，**选择文件夹** 可以更改它。
更改它时，你已经添加的项目不会移动。

**任务编号前缀** 是可选的。
输入最多四个字母或数字，下一个项目的任务就会用它编号。
留空时，Infinitary 会根据项目名称生成一个前缀。

如果项目在其他托管平台上，请询问你的大副。

## 你的 GitHub、GitLab 或 Bitbucket 登录 {#your-github-gitlab-or-bitbucket-sign-in}

为了克隆项目并提交它的改动，Infinitary 会使用你在 GitHub、GitLab 或 Bitbucket 上的登录。

如果你点击 **GitHub 仓库**、**GitLab 仓库** 或 **Bitbucket 仓库** 时还没有登录，这一行会显示 **登录 GitHub**、**登录 GitLab** 或 **登录 Bitbucket**，而不是你的项目。
这个按钮会打开 **设置 → 集成**，你的登录都在那里；参见 [集成](/zh-hans/integrations/)。
对于 GitHub，你要在浏览器中打开的 GitHub 页面上输入一个代码。
对于 GitLab，你可以在浏览器中登录，也可以粘贴一个密钥，适用于 gitlab.com 或你自己的 GitLab 服务器。
对于 Bitbucket，你要在你的 Atlassian 账户上创建一个 API 令牌并粘贴它，适用于 bitbucket.org 上的项目。
密钥表单会写明要在 Atlassian 页面上勾选哪些权限范围。
对于你自己的 Bitbucket Data Center 服务器（8.19 或更新版本），你输入它的地址，并粘贴一个带有 Project read 和 Repository write 权限的 HTTP 访问令牌。
Data Center 项目的改动以拉取请求的形式提交，并且只会在你批准的版本上合并：如果有人在此期间推送，就什么都不会合并，任务会说明这一点。
Data Center 项目也可以选择批量拉取请求，你的船员可以在服务器上读写、通过你的复刻贡献，并在它的拉取请求有新评论、主分支上有检查失败时被唤醒。
Data Center 服务器没有自己的检查日志、运行记录或发布文件：它的检查来自另一个服务，每个检查都链接到其日志所在的位置。
你的 Bitbucket 项目从你所属的工作区中列出；工作区很多时，可能有一些没有被检查到，列表会说明这一点。
Bitbucket 项目的改动以拉取请求的形式提交，与 GitHub 和 GitLab 一样；在此之前添加的项目，从它的下一个任务起也是如此。
Bitbucket 拉取请求的描述以文字形式带上改动说明，图片则留在卡片上。
Bitbucket 项目也可以选择批量拉取请求，它的合并遵循它的主分支在 bitbucket.org 上设置的合并策略和合并队列。
在 Bitbucket 项目上，你的船员还可以读取项目的流水线和某个步骤的日志，把发布文件放进它的 Downloads，并在它的拉取请求有新评论时被唤醒，与 GitHub 和 GitLab 一样；Bitbucket 不提供流水线产物的下载。
你的登录保存在这台电脑上。

如果某个登录失效，会有一张卡片请你重新登录。
需要它的工作会一直等到你重新登录。

## 一个项目中的多个仓库 {#several-repositories-in-one-project}

一个项目开始时只有一个仓库，之后可以包含更多。
项目的页面在 **仓库** 下列出它们，每个仓库各有一个标签页。

你可以用两种方式向项目添加仓库。

- **询问你的大副。**
  说出这个仓库要加入哪个项目。
  你的大副会给你一张卡片，在你点击卡片上的 **添加仓库** 之前，什么都不会添加。
- **自己添加。**
  点击最后一个标签页后面的 **添加仓库**，然后像添加项目时那样，选择文件夹、要克隆的仓库或 **新建仓库**。

仓库的任务使用项目的任务编号前缀。
每个任务在一个仓库中工作，任务的 **信息** 标签页会把这个仓库的名称写在项目旁边。
每个仓库都保留自己的设置，例如 **改动去向**、**合并前先询问** 和 **把关**：选择它的标签页就能更改这些设置。
有多个仓库的项目有自己的名称，可以用 **项目** 框中的 **名称** 来更改。

## 把仓库移到另一个项目 {#move-a-repository-to-another-project}

仓库可以移到另一个项目，也可以自成一个单独的项目。

- **询问你的大副。**
  如果你明确说出要把哪个仓库移到哪里，移动会立即完成。
  如果移动是你的大副提议的，会有一张卡片写明每个仓库移到哪里、哪些任务随之移动，在你点击 **应用移动** 之前，什么都不会移动。
- **自己移动。**
  在仓库的标签页上，找到把这个仓库移到另一个项目的那一行，在那里选择一个项目，点击 **移动**，然后再次点击 **移动** 确认。

仓库会保留它的名称、文件夹和设置。
它的任务随它一起移动，每个任务的编号保持不变。
一个仓库都不剩的项目会从列表中移出：它剩下的任务，连同它的标签和自动化，都并入另一个项目，它的任务编号前缀以后也不会再被使用。
要把两个项目并成一个，就把其中一个项目的仓库都移入另一个项目。

## 标签 {#tags}

每个项目都有自己的一组标签，例如缺陷、功能或想法。
标签有一个名称和一段描述，描述说明哪些任务符合。
标签用来帮你查找任务、给任务分组，除此之外，Infinitary 不会因为标签而做任何事。

项目的页面在 **标签** 下列出它的标签，每个标签都标明有多少个任务带有它。

- **建议标签** 只在项目还没有标签时出现，它请你的大副读一遍项目的任务，并用一张卡片给出建议的标签；你可以通过回复修改这张卡片。
- **添加标签** 会让你填写标签的名称，并说明哪些任务符合。
- **编辑** 可以更改标签的名称或描述。
  改名后的标签仍留在带有它的任务上。
- **移除** 会把标签从每个带有它的任务上去掉，在此之前会先问你一次，并说明有多少个任务。

你也可以让你的大副来添加、更改或移除项目的标签。
移到另一个项目的任务会失去它的标签，除非它原来的整个项目都并入了那个项目。
要给任务加标签，以及按标签查找任务，参见 [任务和船员](/zh-hans/tasks-and-crewmates/#tags)。

## 工作副本 {#working-copies}

你的船员们从不直接在你的项目文件夹中工作。
每个船员都在你的项目的独立工作副本中、在自己的分支上工作。
在你合并改动之前，你的文件保持原样。

## 聚焦于一个项目 {#focus-on-one-project}

有两个或更多项目时，顶栏会显示一个项目按钮。
点击它，或按 ⇧⌘P（Linux 和 Windows 上为 Ctrl+Shift+P），即可打开一排你的项目。
每个项目按钮都会计数等你处理的任务和正在进行的任务。
选择一个项目，窗口就会聚焦于它。

当一个项目处于聚焦状态时：

- “任务”面板和任务看板只显示这个项目的任务。
- “动态”只显示关于这个项目的条目，以及不属于任何任务的条目。
- 关于其他项目的卡片会等到聚焦改变后再出现。
  不会关闭任何内容，每个项目仍会发送通知。
- 项目按钮旁边有一行短字，说明其他地方有多少个任务在等你，例如“其他地方有 2 个在等你”。
- 你发的每条消息都会让大副知道当前聚焦的项目。
  除非你指明另一个项目，新工作会放进这个项目，大副的回答和对多个任务的操作也只涉及这个项目，并说明略过了什么。

想在不聚焦的情况下看看一个项目的工作在哪里运行，可以把指针移到窗口中央的某个船员上，或在手机上轻点它。
它的概要打开时，其他项目的每个船员在每台电脑上都只剩四分之一的亮度，谁也不会移动。
关闭概要，亮度就会恢复。

点击项目按钮旁边的 **×**（**显示所有项目**），或在那一排中选择 **所有项目**，即可再次看到全部内容。
Infinitary 重新启动后会记住你的聚焦。

## 改动如何进入你的项目 {#how-changes-reach-your-project}

在 **设置 → 项目** 中打开一个项目，选择它完成的工作如何合并。
**改动去向** 提供：

- **拉取请求**：每个改动都在 GitHub、GitLab 或 Bitbucket 上以拉取请求提交。
- **批量拉取请求**：你已批准的改动会合成一个批量拉取请求，每个改动一个提交，并在检查通过后合并。
- **本地合并**：改动在这台电脑上合并到项目中，不经过拉取请求。

只存在于这台电脑上的项目只提供 **本地合并**。

改动准备好后，负责它的船员会给你一张合并卡片。
卡片上的按钮会说明它做什么，例如 **合并拉取请求**、**合并分支** 或 **随下一批改动合并**。
如果检查仍在运行，按钮会显示 **检查通过后合并**，Infinitary 会在检查通过后合并。

**合并前先询问** 决定由谁来合并。
新项目默认开启它，所以完成的工作会等你确认。
关闭它后，通过检查的工作可以不经询问直接合并。

**把关** 设置工作检查的严格程度：**快速**、**默认** 或 **谨慎**。

**参考工作流** 填写 GitHub 项目的工作流文件（如 `.github/workflows/early-tests.yml`），它们的检查会显示在每个改动上，但从不阻止它合并，也不阻止这批改动合并。
输入这些文件，用逗号分隔，然后按 **保存**。
GitHub 分支规则要求的检查仍会在 GitHub 上阻止合并。

对改动通过拉取请求进入的项目，**说明 AI 协助** 默认开启。
船员审查他人的拉取请求时，发布的评论以一行说明由 Infinitary 船员撰写的文字开头。
修改这一行并按 **保存**，或关闭开关不加这一行。

## 移除项目 {#remove-a-project}

1. 在 **设置 → 项目** 中打开这个项目。
2. 点击最后一行的 **移除**。
3. 再次点击 **移除** 确认。

移除会把项目从列表中去掉。
它的文件夹和已完成的任务会保留。
再次添加时，会使用它留在你的项目文件夹中的文件夹，而不是再克隆一份，项目会以默认设置重新开始。
如果项目仍有任务，Infinitary 会列出它们的名称，你需要先完成或放弃它们。

在有多个仓库的项目中，**移除** 只移除当前所选标签页对应的那个仓库，项目会保留其余的仓库。
